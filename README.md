# МИТОпаспорт — врачебный калькулятор интерпретации

Веб-приложение для врачей: помогает интерпретировать результаты лабораторной панели «МИТО-паспорт» (15 показателей иммунно-клеточного и митохондриального статуса). Врач вводит только числовые значения — приложение возвращает структурированную клиническую интерпретацию на трёх уровнях: по каждому показателю, по шести функциональным контурам, по паттернам с выбором ведущего. Медицинская логика приведена к пособию «Интерпретация митопаспорта» (2-е изд., Астана, 2026).

Не диагностическая система. Не заменяет клиническое мышление и не назначает лечение — формирует гипотезы и направления для дообследования.

## Быстрый старт

```bash
npm install
npm run dev       # http://localhost:5173
npm run build     # типы (tsc -b) + production-сборка в dist/
npm run lint       # oxlint
npm run preview    # просмотр production-сборки
```

## Архитектура

Жёсткое разделение между **медицинским содержанием** (редактируется без знания TypeScript-логики) и **расчётным движком** (не знает о конкретных показателях/паттернах — работает с тем, что ему передали):

```
src/
  config/      Редактируемый медицинский слой: показатели, референсные зоны,
               контуры, паттерны, правила безопасности, демо-набор данных.
  engine/      Чистый расчётный движок. Не импортирует src/config напрямую —
               получает конфигурацию как параметр (CalculationConfig).
  components/  UI-компоненты (общие примитивы в ui/, блоки результата в result/).
  pages/       Три экрана: HomePage, InputPage, ResultPage.
  state/       React-контекст MitoPassportContext: ввод, расчёт, пример, очистка.
```

Движок никогда не импортирует `src/config` — это сознательное ограничение. Вся конфигурация собирается один раз в `src/config/index.ts` (`calculationConfig`) и передаётся в `runCalculation(inputs, calculationConfig)` из `src/state/MitoPassportContext.tsx`. Это значит, что **весь медицинский слой можно поменять, не трогая ни одной строки в `src/engine`.**

## Как редактировать медицинский слой

Все файлы — в `src/config/`. Типы для каждой структуры — в `src/engine/types.ts`.

### `indicators.ts` — каталог показателей

Что измеряется: 7 показателей Блока 1 (0–100%) и 8 показателей Блока 2 (ΔNADH, −100…100%, биполярные). Здесь — лейблы, единицы, подсказки, min/max/step для полей ввода. **Не содержит референсных зон** — порядок и значения шагов изменить можно свободно, добавление нового `IndicatorId` требует также завести его в `engine/types.ts` (union `IndicatorId`).

### `referenceRanges.ts` — референсные зоны и риск-баллы

Для каждого показателя — массив зон (`ReferenceZone`): `id`, `label`, `riskScore` (0–3), `min`/`max` (включительно), `meaning` (текст уровня 1). Зоны должны покрывать весь диапазон показателя без пропусков.

**Важно:** у всех показателей Блока 2 (ΔNADH, комплексы дыхательной цепи и т.д.) в конфиге стоит `isEditablePlaceholder: true`. Это означает, что числовые пороги — черновые, не калиброваны клинически, и приложение явно показывает это предупреждение в интерфейсе (раздел «Блок 2» на экране ввода). Перед реальным клиническим использованием эти пороги нужно заменить на валидированные значения — сами зоны (label/meaning) трогать не обязательно, достаточно скорректировать `min`/`max`.

### `zoneGroups.ts` — общие группы зон

Сокращения для формул: «ниже целевой», «выше целевой», «проба отклонена» (отрицательная область) и т. п. Используются и паттернами, и контурами.

### `contours.ts` — шесть функциональных контуров (глава 5 пособия)

Каждый контур — ключевые и дополнительные показатели по матрице 5.2, `requiredIndicators` (без них контур «не оценён», раздел 5.6) и список `states`: состояния проверяются сверху вниз, срабатывает первое выполненное. Если ни одно не выполнено, движок выводит «наблюдение» (одиночное отклонение) или «изменён, не классифицирован». Флаг `ifMeasured: true` в условии делает компонент необязательным при неполном объёме исследования. Ведущий контур выбирается в `engine/contours.ts` по ориентирам раздела 5.4.

### `patterns.ts` — 15 паттернов (глава 6 пособия)

Каждый паттерн — `requiredConditions` (обязательные компоненты формулы) и `supportingConditions` (компоненты «±», повышают уверенность), уровень `level` A–E и `conclusionLine` (строка для заключения). `subtypes` — глубина или стадия (паттерны 1, 12, 13). Если для обязательных условий не хватает измеренного показателя, паттерн получает статус «не оценён» (правило 6). Ведущий паттерн выбирается в `engine/priority.ts` по восьми правилам раздела 6.3; правила 7 и 8 используют отметки врача на экране результата.

### Клинический контекст (этап 3)

- `panels.ts` — комплектации Light, Standart, Pro, Max (раздел 1.6). Врач выбирает комплектацию или калькулятор определяет её по введённым показателям; показатели вне выбранной комплектации в расчёт не берутся.
- `clinicalContext.ts` — условия забора и события предшествующих недель (раздел 1.1) с подсказками к правилу 7, срок от перенесённой инфекции (стадии паттерна 14), клинические находки для красных флагов, клинические ситуации таблицы 7.4.
- `redFlags.ts` — красные флаги раздела 9.3: флаг подтверждается при совпадении числового условия и клинической находки, при одном числовом условии выводится подсказка проверить клинику.
- `workup.ts` — базовый набор анализов (7.1), анализы по показателям (7.2), границы НЛС и типа реакции по Гаркави (7.5). Анализы по паттернам (7.3) хранятся в `patterns.ts` (`whatToCheck`, `excludeFirst`).

### `safetyRules.ts` — флаги безопасности и статические тексты

`dynamicSafetyRules` — правила вида «если выполнено условие `when` (тот же DSL) — показать флаг уровня `info`/`warning`/`critical` с текстом». `staticSafetyNotes` — не зависящие от ввода тексты: red flags, когда не интерпретировать изолированно, когда направлять на стандартное обследование, общий disclaimer.

### `example.ts` — демо-набор для кнопки «Загрузить пример»

`exampleInputs` — заранее подобранный набор значений, проверенный вручную против `referenceRanges.ts`/`patterns.ts`, чтобы демонстрировать содержательный кейс (несколько паттернов разных уровней, изменённые и сохранные контуры). При правке референсных зон или паттернов стоит перепроверить, что пример всё ещё ведёт себя ожидаемо.

## Расширение

- **Новый показатель:** добавить `IndicatorId` в `engine/types.ts`, описание — в `config/indicators.ts`, зоны — в `config/referenceRanges.ts`, при необходимости включить в контуры/паттерны.
- **Новый контур/паттерн/правило безопасности:** добавить запись в соответствующий файл `config/*` — движок (`engine/contours.ts`, `engine/patterns.ts`, `engine/safety.ts`) уже умеет работать с произвольным набором записей и не требует правок.
- **Композитные индексы (SRC, интегральный митохондриальный индекс и т.п.):** в `engine/types.ts` уже зарезервирован тип `DerivedIndexDefinition` как точка расширения — формулы сознательно не реализованы, чтобы не изобретать клинически непроверенные расчёты.
